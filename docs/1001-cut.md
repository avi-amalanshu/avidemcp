# cut

> Remove one range and join what's left; exact mode re-encodes frame-accurately, copy mode is lossless but resumes on an I-frame.

Tree: `1001` < `100` Ranges < `10` One edit per call < `1` Edit < root ([AGENTS.md](../AGENTS.md))

## Call

```
cut {"input": "clip.mov", "start": 4, "end": 6.5}
cut {"input": "clip.mov", "start": 4, "end": 6.5, "mode": "copy"}
-> {"output": "clip.cut.mov", "kept": [[0.0, 4.0], [7.0, 14.4]], ...}
```

| Argument | Default | Meaning |
|---|---|---|
| `start` | required | first second removed |
| `end` | required | first second kept after the gap |
| `mode` | `"exact"` | `exact`: frame-accurate re-encode to H.264 MP4; `copy`: no re-encode, input's container |
| `snap` | `true` | copy mode only; see below |
| `crf` | 18 | exact mode only |
| `output` | `<stem>.cut.mp4` (exact) or `<stem>.cut.<input ext>` (copy) | |

## Modes

- `exact` removes exactly the frames in `[start, end)` and the matching audio, and encodes once.
  A range that touches either end of the clip works like `trim`.
- `copy` takes seconds and loses no quality. With `snap: true`, playback resumes at the first
  I-frame at or after `end`, so a little more is removed; `kept` gives the source ranges that
  survived. The call fails when no I-frame follows `end`; use `exact` or `snap: false`.
- `copy` with `snap: false` resumes exactly at `end`, on P-frames that now predict from the last
  frame before `start`. The motion after the cut moves the picture from before it: Avidemux's
  accidental datamosh, made on purpose. It is most controllable on a file made by `prepare`; see
  [EXAMPLES.md](../EXAMPLES.md).

## When to use which

- `exact` whenever the join point matters.
- `copy` to drop a long stretch quickly when `probe` shows an I-frame near `end`.
- For several edits to one file, one `render` with `cut` ops encodes once instead of once per call.
